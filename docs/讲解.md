# 这版应用怎样工作

书籍信息来自 Open Library，个人书库由你自己添加。推荐从随项目附带的
21 本休闲文学作品中选取；这个候选目录带来源链接，可以离线使用，也不会被
当成你的阅读记录。新增书籍则可以实时查询目录之外的作品。

默认兴趣是小说、短篇和旅行散文。推荐页可以输入 `推理，短篇` 等兴趣。
历史策略参考实际保存的书和评分；兴趣策略匹配体裁或主题；探索策略尝试其他
文学体裁。最后保留一个探索位置，其余优先放历史或兴趣匹配的作品。

## 一个具体例子：添加《The Hobbit》

1. `app.sh` 打开菜单，你选择 Add Book。
2. `ui/library_screen.sh` 收集书名和作者，交给 `manage_library.sh lookup`。
3. workflow 调用 `fetch_book_metadata.sh`，后者调用 `catalog.sh` 查找候选。
4. 你选中正确的书籍，再选择阅读状态和是否拥有。
5. workflow 把书籍交给 `book_database.sh add`。数据层检查重复和字段，保存 CSV，
   然后返回保存后的记录。

脚本传递的是一行一个 JSON 对象，例如下面这个精简示例：

```json
{"id":"/works/OL27482W","title":"The Hobbit","author":"J.R.R. Tolkien","genre":"Fantasy"}
```

真实记录还包括年份、主题、来源链接等字段。JSON 可以正确处理书名里的逗号、
引号和中文，`jq` 用来选择和处理这些字段。持久保存时，数据层才把 JSON 转成
CSV；读取时再转换回来。其他文件不知道 CSV 怎样解析。

## 并行和管道在哪里

`workflows/get_recommendations.sh` 中的 `&` 会让三种推荐程序同时开始。
`$!` 取得刚启动程序的进程 ID，`wait` 等待对应程序结束。这段时间里，终端显示
各策略的状态。三个输出文件暂存结果，结束后合并并进入真正的管道：

```bash
cat history.jsonl interests.jsonl discovery.jsonl | refine_recommendations.sh
```

这是流程示意，实际代码使用独立的临时目录。refine 从 stdin 读候选，排除书库中
已有的书、合并重复推荐及理由，再输出短名单。推荐界面只负责展示和让你选择保存。

每个程序的 stdout 留给 JSON 数据，stderr 留给进度和错误。因此，进度提示不会
混进下一段程序要处理的书籍数据。某个策略失败时，workflow 会丢弃它未完成的输出，
其他成功策略仍可贡献结果。

## 需要知道的范围

这些推荐是可解释的规则，没有在应用内部调用 LLM。空书库没有历史证据，历史策略
会跳过；低评分书籍也不作为正向证据。候选范围目前就是随项目附带的目录。
年份是来源目录中的年份，不能一概当成作品的首次出版年份；类型是项目的分类。

`--demo` 使用临时样例书库，退出后删除。正式书库初始为空。无声视频展示三项操作，
你的配音完成后才能满足作业的带旁白视频要求。

所有文件的输入、输出和职责见 [WORKFLOW.md](WORKFLOW.md)，具体接口见
[INTERFACES.md](INTERFACES.md)。
